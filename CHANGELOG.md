# Changelog

## 0.0.6

- **Fresh base.** `[branches] fresh_base` (allow, warn, approval or deny). When it is on, the hook fetches origin's copy of the landing branch as an agent's session starts, and tells the agent whether it has the latest code and, if not, how far behind it is and how to update (`git pull --rebase origin main`). Work that started behind and never caught up shows as `BASE_STALE` in the brief, and is held at the setting's strictness. When the agent updates, by rebasing or merging, the commits it pulled in are not counted as its change, including any pushed after its session started. Only a new session is checked, not a resume or compaction. The fetch gives up after 5 seconds, never asks for a password or ssh passphrase (ssh runs in batch mode unless you set your own ssh command) and leaves nothing running; a failed fetch is said and never erases or holds anything. New setups turn it on as `warn`; existing policies are unchanged until you set it. Checked on your machine; the CI gate does not re-check it.
- **Files that change together.** A `[[require]]` rule: when a change touches `when`, it must also touch `also` (for example `when = ["src/api/**"]`, `also = ["docs/api/**"]`). The agent is told the rule when its session starts; when it stops without the update (staged or not), Claude Code is asked once to make it, also after it was first asked to fix a failing check; the brief reports `ALSO_CHANGE_MISSING`, held at the rule's `severity` (`approval` by default). An optional `why` is said to the agent and in the brief. 05 checks that a file there changed, not what the change says.
- The guided setup asks which folders must be updated whenever code changes, and how strict fresh base is. An organisation floor can set `branches_fresh_base` and add `require` rules. A policy using either rule needs use05 0.0.6 or newer; older versions are told to upgrade.
- **Fixed: a scope written as one string.** `--scope "src/** docs/**"` or `--scope src/**,docs/**` is now read as two patterns, not one that matches nothing (which put every changed file outside the plan). Found when a real agent declared its plan that way. `--exclude` too.
- **Fixed: agents working in a subfolder.** When an agent's session moved two or more folders below the repository's top (`apps/web/app/...`), 05 looked for its state outside the repository. Every hook then failed with "creating the state directory: Read-only file system" and nothing was checked; from shallower folders it quietly wrote its state to a `.git/05` folder above the repository. 05 now finds the repository's own `.git` from any folder.

## 0.0.5

- **A better-looking setup.** `use05 init` and `use05 policy --edit` now walk through seven numbered steps with bold questions, the default highlighted, clear prompts and a summary table before anything is written.
- **More than one environment per level, and any branch.** Two dev environments on their own branches (`dev` and `dev-eu`, say) can sit on the same level; the setup asks you to name the second one. Any branch can be added as an environment by name, and an environment can have any name with a `level` of dev, uat, pre-prod or prod. As a flag: `--env dev-eu=eu-main:dev`. `use05` shows environments on one level side by side. A policy using `level` needs use05 0.0.5 or newer; older versions are told to upgrade.
- **Clearer strictness choices.** The questions now say what happens: for work outside the plan, "let it, but ask me before each edit outside the plan", "stop the agent; a person approves a wider plan", or "stop the agent and refuse the change".
- A landing branch that does not exist (a typo) is questioned before it is used. Rails' `db/migrate` is suggested as add-only. A session shorter than a minute reads "under a minute".
- Scripts that pipe answers into `use05 init --guided` get one more question after the environments ("Add another branch as an environment"); answer it with an empty line. `--env staging=uat` still works: a common name gives its own level.
- The README and site lead with the five principles behind the name: policy, gates, intent, evidence and review.

## 0.0.4

- **Guided setup.** On a terminal, `use05 init` now asks a few plain questions before it writes anything: who works in the repository (setting how strict the rules start), which branch changes land on, which long-lived branch is dev, uat, pre-prod or prod, the checks, folder and file rules, how strict to be, and how changes land. It shows a summary and asks before writing. The same answers work as flags (`--team`, `--target`, `--env dev=main`); `--defaults` skips the questions.
- **Change your settings without editing the file.** `use05 policy --edit`, or `use05 init` again, asks the same questions with your current settings as the defaults. Comments and settings the questions don't cover are kept.
- **Environments.** `[[environment]]` records which branch is which environment, lowest first. Bare `use05` shows them with each branch's commit, the brief says where a change lands (`lands on main (dev)`), and environment branches are never deleted. Rules for promoting between environments come later. A policy with environments needs use05 0.0.4 or newer; older versions are told to upgrade.
- Smaller fixes: a file name with a newline in it is read correctly; very large changes use less memory; the brief reads receipts once; refusal reasons are recorded only on refusals; files directly in a split folder show as `src/*`; a subagent's type is not hidden by a line that does not name it.

## 0.0.3

- **Briefs for large, long sessions.** The brief's outcome now counts lines added and removed, overall and per area, and groups the files into at most eight named areas (`src/billing/ · 285 files · +28,500 −11,400`) instead of top-level folders only. Files outside the declared scope are grouped by area too. `brief --json` keeps `areas` as before and adds `area_summary` and `outside_scope_areas`. A new Session section digests what the agent did, in at most four lines: how long it ran, turns, tool calls, what 05 refused and why, which checks ran along the way and how they ended, and the subagents that took part.
- **Subagents.** Claude Code and Codex subagents are held to the same rules, and now every action they take is recorded with the subagent that took it. Each subagent is told the rules when it starts. Run `use05 init` again after upgrading to install the new hooks.
- **Project-level npm install.** `npm install --save-dev @use05/cli` then `npx use05 init` now works end to end: the agent hooks and the git pre-push hook it writes find the project's own copy in `node_modules/.bin`, in agents' worktrees too. Before, they looked for `use05` on PATH only, so with a project-level install they quietly did nothing. A use05 installed for the whole machine still comes first.
- **Faster on big changes.** The check for weakened tests reads from git once, not once per file: a change of 700 new Rust files briefs in about a third of a second instead of five.

## 0.0.2

- **Folder and file rules.** In `.05/policy.toml`, `[protect]` can now mark paths `locked` (never changed; no approval clears it), `append_only` (new files only, for example database migrations; edits, renames and deletions are refused), `no_delete`, and `no_read` (agents may not open them). Agent hooks refuse these before they happen, through file tools and the shell; the gate and the CI gate deny them. A person can bypass a rule for one exact change with a stated reason, unless the path is listed in `absolute` or `bypass = false`. Rules are read from the change's base, so a change cannot unlock a file and edit it in one go. An organisation floor can add rules and turn bypass off. `no_read` is advisory: it holds only where an agent's own hooks report the read.
- **`[use05] min_version`.** A policy can name the oldest use05 that reads it, and `use05 init` writes it. An older version is told to upgrade instead of failing on a rule it does not know. Versions before 0.0.2 cannot read this line, so everyone working on a repository set up by 0.0.2 needs 0.0.2 or newer.
- Claude Code hooks now also see Read, Grep and Glob, so `no_read` can hold. Run `use05 init` again after upgrading: it now updates hooks an older version installed, keeping other tools' hooks.

## 0.0.1

First public version: init, start, prove, brief, approve, verify, policy, doctor and bypass; Claude Code and Codex hooks; a git pre-push gate and a CI gate; organisation policy floor; signed receipts on `05-receipts/*` branches; trusted-key expiry; local collision awareness between parallel agent sessions.
